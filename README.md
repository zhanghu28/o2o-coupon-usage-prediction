# O2O 优惠券核销预测（天池 O2O Coupon Usage Forecast 复现与改进）

> 《数据科学与工程》课程期末项目 · 完整可运行
> 数据清洗 → 数据集成 → 特征挖掘 → 建模预测 → 可视化 → 结论，全流程一条命令跑通。

---

## 1. 这个项目做了什么（30 秒版）

天池 2016 年比赛：给用户发优惠券，**预测他领券后 15 天内会不会去消费（核销）**。
比赛评分不是普通 AUC，而是"**先按每张优惠券分组算 AUC，再对所有券求平均**"。

本项目用官方 175 万行离线数据，完成了：

| 环节 | 做了什么 | 产物 |
|---|---|---|
| 数据清洗 | 日期非法值、折扣字段拆解、重复行、时间逻辑校验、缺失填补 | `outputs/tables/01_数据质量报告.csv` |
| 数据质量监测 | 缺失率 / 重复 / 异常券 / 长尾分布统计 | 同上 + `fig01`~`fig05` |
| 数据集成 | 从 1 张流水账拆成 4 张画像表（用户/商家/券/用户×商家），再合并成宽表 | `outputs/tables/02_集成汇总.csv` |
| 特征挖掘 | **point-in-time（只看过去）时序特征**，彻底避免"用未来预测未来" | `outputs/tables/03_特征清单.csv` |
| 建模预测 | LogisticRegression / LightGBM / XGBoost / HistGBDT / **LGB分组感知** 五个模型 | `outputs/tables/06_模型评估指标.csv` |
| 可视化 | 12 张论文级图表（走势、分布、ROC、校准、增益、热力图……） | `outputs/figures/` |
| 结论 | 自动汇总数据层/模型层/特征层/业务层结论 | `outputs/结论摘要.md` |
| 提交 | 天池格式提交文件 | `outputs/submission.csv` |

**主要结果**：官方口径（券分组平均 AUC）**0.5807**，全局 AUC **0.7438**；
预测最高 10% 人群的实际核销率 **36.5%**，最低 10% 只有 **2.9%**，相差 **12.4 倍**。

## 4. 这个项目的三个技术要点（答辩会被问）

**① 为什么必须用时间切分，不能随机切分？**
随机切分时，同一个用户 3 月的数据在训练集、4 月的数据在验证集，模型等于"看过答案"。
本项目的实验数据：随机划分全局 AUC = **0.9161**，时间划分 = **0.7613**。
差的 0.15 全是虚高。详见 `outputs/tables/06_数据划分对比.csv`。

**② 什么特征会泄漏答案？**
`u_redeem_rate`（用户历史核销率）如果直接在整段时间上统计，等于把这条样本自己的 label
算进特征里——项目里实测这种特征单枪匹马就能把训练集 AUC 干到 **0.98**，一上验证集立刻崩。
所以本项目所有"跟核销结果有关"的统计都改成 **point-in-time**：只统计当前样本日期**之前**发生的事。
见 `src/03_特征工程.py` 里的 `add_prior()`。

**③ 为什么全局 AUC 高反而比赛分低？**
官方指标是券内排序。券的面额、门槛、这张券的历史核销率，在"同一张券分组内"是常量，
对组内排序**毫无贡献**，却会抢走模型注意力。
本项目的"LGB分组感知"模型把这些券内常量特征删掉重训，券分组 AUC 从 0.5535 → **0.5807**。

## 5. 与冠军方案的差距（诚实说明）

冠军方案（[wepe/O2O-Coupon-Usage-Forecast](https://github.com/wepe/O2O-Coupon-Usage-Forecast)）线上约 0.80。本项目 0.58（券分组 AUC），差距来自：

1. **没用到线上行为表**（`ccf_online_stage1_train.csv`，约 460MB 的点击/浏览/领券行为）——这是冠军方案的大杀器；
2. **没做多模型融合**（冠军用 xgb + lgb + gbdt 加权平均）；
3. **特征深度有限**（冠军构造了上百个窗口特征：7/15/30 天滑动窗口、用户-商家交叉统计等）。

这三条也正是本项目"后续工作"部分写的内容。
